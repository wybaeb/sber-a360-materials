# Заполненный пример карты: кредитная карта, падение активации

Разбор образца со встречи Шага 1. Данные условные, структура и порядок величин —
типовые для розничного банка. Ваша карта делается по этому же маршруту.

> **вопрос → метрика → категории данных → источники → проверка качества → master-source → действия**

---

## 1. Вопрос

**Почему падает конверсия в активацию кредитной карты?**

Вопрос управленческий, а не аналитический: за ним стоит решение — вкладываться в доставку,
в коммуникацию или в упрощение оформления. Карта строится под это решение, а не «про карты вообще».

## 2. Метрики

| Метрика | Тип | Единица | Частота наблюдения |
|---|---|---|---|
| Активация за 30 дней | опережающая | % от выдач | еженедельно |
| Срок доставки (TAT) | опережающая | дни | еженедельно |
| Отказы на выпуске | опережающая | % заявок | еженедельно |
| Доход по продукту | запаздывающая | ₽/мес. | ежемесячно |

## 3. Категории данных

- **Клиентские** — профиль, канал привлечения, сегмент
- **Процессные** — статусы заявки, отметки времени по шагам, статусы доставки
- **Транзакционные** — первая операция по карте (это и есть факт активации)
- **Справочные** — тарифный план, кодификатор каналов, справочник отделений

## 4. Источники

| Источник | Что даёт | Владелец | Обновление | Доверие |
|---|---|---|---|---|
| CRM | заявка, канал, статусы до решения | владелец CRM | онлайн | доверяю |
| DWH, витрина «Карточные продукты» | выдачи, активации, доход | владелец витрины | раз в сутки | доверяю |
| Курьерская служба (внешний подрядчик) | статусы доставки | менеджер договора | выгрузка по запросу | проверяю |
| Навигатор BI | сводный дашборд продукта | владелец дашборда | раз в сутки | доверяю |

## 5. Проверка качества

- **Частота:** витрина обновляется раз в сутки — под еженедельное решение достаточно.
- **Полнота:** 3 % заявок без корректного адреса — по ним срок доставки не считается вовсе.
- **Дубли:** заявка, поданная в приложении и на сайте, создаёт две записи об одном клиенте;
  без дедупликации конверсия занижена.
- **Определения:** в CRM «активация» = выпуск карты, в витрине = первая операция.
  **Это и есть источник спора о цифрах.**

## 6. Master-source

**Витрина «Карточные продукты» в DWH** — единственная цифра активации для комитета.

Почему она: считает активацию по факту первой операции (то есть по смыслу решения, а не по
техническому событию), прослеживается до транзакции, есть живой владелец, обновляется раз в
сутки. Цифра CRM остаётся рабочей для операционного контроля, но на комитет не выносится.

## 7. Action plan — то, ради чего строилась карта

| Что | Кому | Срок |
|---|---|---|
| Сверить определение активации в CRM и в витрине, зафиксировать письменно | владелец витрины | неделя |
| Запросить регулярную выгрузку статусов курьерской службы, а не по запросу | менеджер договора | две недели |
| Починить 3 % заявок без адреса — разобраться, на каком шаге теряется поле | владелец процесса | месяц |

## Что в этом примере типично, а что — находка

**Типично:** источников оказалось четыре, а не двадцать; половина проблем — не в чистоте
данных, а в разных определениях одного показателя.

**Находка кейса:** пока «активация» означает разное в двух системах, любое решение по
продукту обсуждается через спор о цифрах. Master-source здесь — не техническое, а
управленческое решение, и принимает его руководитель, а не владелец системы.
